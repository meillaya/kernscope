JSON LIBRARY CHOICE (documented deviation resolution)
  nlohmann/json is NOT in the devenv profile (verified 2026-08-14: no
  nlohmann/json.hpp reachable from the profile CPATH; CMAKE_PREFIX_PATH
  empty). todo 8 MUST NOT modify devenv files, so nlohmann_json could not be
  added. llvm::json (polykernel precedent) would couple libs/db to
  LLVMSupport. RESOLUTION: self-contained ~350-line JSON value model in
  kernscope/db.h (recursive-descent parser with \uXXXX+surrogate support,
  128-level nesting cap, canonical sorted-member writer, shortest-round-trip
  numbers via std::to_chars). Record envelope is fixed and small; zero
  dependencies; fully gtest-covered.

DESIGN (per docs/research/autotuner-research-brief.md)
  §1 Triton disk cache: config hashed into the key (config_canonical =
  canonical JSON dump), configs_timings pairs = one record per config,
  winner re-picked by min median without re-benchmarking = query_best.
  §2 MetaSchedule JSONDatabase: workload-keyed records (shape_hash),
  NDJSON, warm-start seeding (load merges; dedupe/replace on identical
  (gpu_arch, kernel_family, shape_hash, config) keys).
  Forward-compatible loader: schema_version > 1 -> warn + skip with line
  number; corrupt line -> warn + skip with line number; loading continues.

RISKS / DEVIATIONS
  1. JSON library: self-contained minimal JSON model instead of
     nlohmann/json (not in devenv profile; MUST NOT touch devenv.nix) or
     llvm::json (would drag LLVMSupport). See rationale in db.h header.
  2. Canonical serialization: save() emits sorted member order (deterministic,
     diffable, dedupe-key-stable) - member order of hand-written files is
     not preserved on re-save (logical content identical).
  3. put() rejects (std::invalid_argument) non-object config / non-finite
     numbers: JSON has no NaN/Inf literal, so this keeps save() emit-safe.
  4. Full `cmake --build build` exit 1 is a transient parallel-worker
     condition (todo-7 report_test.cpp Werror nodiscard); kernscope_db and
     kernscope-db-test compile clean under the same -Wall -Wextra -Werror.
  5. Blank lines and CRLF line endings are tolerated silently (not warned);
     only malformed content is warned.
