RISKS / DEVIATIONS
------------------
  * MC brittleness encountered (as anticipated in the task): LLVM 21.1's
    AMDGPUAsmParser validates hipcc/clang's `.amdgcn_target
    "amdgcn-amd-amdhsa--gfx1101"` against the TargetID it computes from the
    STI. When the CPU is embedded in the triple ("...--gfx1101"), the
    computed TargetID differs ("...-unknown-gfx1101-gfx1101") and llvm-mc
    itself rejects the file. FIX (documented in code): pass the bare
    "amdgcn-amd-amdhsa" triple to MC and give the CPU to
    createMCSubtargetInfo() separately; TargetID then matches exactly.
  * Scope fallback decision: NOT needed. The MC path parses the full
    hipcc-generated file (incl. .amdhsa_kernel descriptor + .amdgpu_metadata
    YAML) and hand-authored WMMA/MFMA fixtures. The parser's contract is
    "hipcc/clang -S output" (the analyzer's exact input), with real
    RDNA3/CDNA ISA fixtures as bonus coverage.
  * No ROCm device libraries linked; SASS never parsed (ISA text only).
  * One test-name note: ctest -R is case-sensitive; suite is "AmdParse",
    so `ctest -R amdparse` matches zero tests. Verified with
    `ctest -R "AmdParse"`. (Planned acceptance cmd was case-insensitive.)
