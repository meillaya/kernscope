Design notes / risks (deviations from the literal plan wording are in the
header comments of capture.h / intercept.cpp):
- driver-API coverage extended by cuModuleGetFunction + cuLaunchKernel/Ex:
  cuFuncGetParamInfo arg introspection is meaningless without a driver-API
  launch interceptor; cuModuleGetFunction provides the CUfunction->name link
  so the bundle's kernel-name field is satisfiable on the driver path
  (22-symbol table; the plan's "full API table").
- runtime-API launch records carry NO arg bytes (opaque void** args with no
  per-arg sizes at the boundary; the sizes live in the kernel image).
  Byte-exact runtime-path args are todo-44 CUPTI functionParams; the driver
  path + the mock scenario cover byte-exact args now.
- graph launch records carry the exec handle only (nodes unreachable via
  LD_PRELOAD) - CUPTI (todo 44) walks graph nodes.
- the shim is compiled+unit-tested against the MOCK only; real-NVIDIA
  interception is rental-gated (scripts/rental-validate.sh).
