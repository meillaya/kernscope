THE PASS (design)
-----------------
* Stride analysis on smem GEPs of each addrspace(3) allocation (alloca AND
  the internal-addrspace(3)-global form clang emits for __shared__ arrays,
  incl. the ptr-addrspacecast ConstantExpr + two-GEP chain, verified
  against a real clang -O0 probe).
* Lane var: llvm.nvvm.read.ptx.sreg.tid.x / .laneid / amdgcn.workitem.id.x;
  each GEP index classified as constant / affine (add/sub/mul/shl/zext/
  sext/trunc chains) / data-dependent.
* Stride per index = coeff * alloc-size of the GEP's indexed type
  (llvm::gep_type_iterator — exactly what the GEP computes, no re-derived
  dim math).
* Bank footprint = the analyzer's todo-16 formula (analyze_banks.cpp
  compute_banks): 32 banks x 4-byte words, way = max multiplicity over the
  32-lane warp; conflict provable iff way > 1 on a NON-innermost index
  (the +1 pad only rescues non-innermost strides; innermost-only conflicts
  and unaligned strides are honestly declined).
* +1 column pad: innermost dim k -> k+1; rewrite = type change propagated
  through the whole GEP chain (alloca setAllocatedType in place; globals:
  new GlobalVariable + RAUW, name preserved); GEP nowrap flags (inbounds
  nuw) preserved.
* Budget guard: libs/arch (kernscope/arch.h) get_arch/has_arch — arch from
  "kernscope.pad.arch" fn attr, then nvvmarch/amdgpu-arch module flags;
  padded bytes must fit smem_per_block_max_bytes (else smem_per_sm_bytes).
  wave64 (AMD CDNA) archs declined explicitly (wave32 model only, per
  research brief §2.2). Two-phase: all analysis before any mutation.
