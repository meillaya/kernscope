MODEL / SCHEMA DESIGN (machine-readable by construction)
  KernelReport { kernel_name; metrics map<string,double> (flat numeric - NO prose); limiter string;
                 warnings/suggestions vector<Finding> }; Finding { id; severity; evidence map<string,string> }.
  Evidence values are strings so numeric fields stay machine-readable while the model stays simple; the special
  evidence key "text" is the one-line human summary the TEXT renderer prints (owner bullets), falling back to id.
  JSON envelope: schema_version/report_type/kernel{name}/metrics{...}/limiter/warnings[]/suggestions[].
  HTML: <script id="report-data" type="application/json"> payload; "</" escaped as "<\/" (valid JSON escape,
  decoded by JSON.parse/json.loads); 0 http(s) references; JS renders via textContent only (no innerHTML).
  All renderers validate first and throw SchemaViolation - never a silent render.

NOTES / DEVIATIONS FROM THE BRIEF
  1. CMake 4.3.4 (nixpkgs) BUG WORKAROUND: after any pkg_check_modules call, variable-sourced
     target_include_directories() is silently DROPPED from the generated Ninja INCLUDES (minimal-repro-verified:
     plain set() var, $CACHE{} var, hardcoded path all vanish; hardcoded survives only without pkg_check_modules).
     The gtest -I therefore travels via target_compile_options as "-isystem<path>" (documented in
     libs/report/CMakeLists.txt). IMPORTED_TARGET mode also drops includes, so plain pkg_check_modules vars are used.
     This is the SAME root cause that initially broke the sibling todo-6 arch-test (GTest::gtest_main target
     unresolvable - no GTestConfig.cmake in CMAKE_PREFIX_PATH).
  2. jsonschema pip is NOT in the devenv python (probed: import fails) -> committed minimal draft-2020-12 subset
     validator tests/report/validate_json.py (deterministic, no pip dependency; reused by the gtest via subprocess).
  3. gtest 1.17.0 headers trip -Wcharacter-conversion under clang-21 -Wextra -> gtest include dir is -isystem
     (third-party headers must not fail the -Werror gate).
  4. [[nodiscard]] was REMOVED from the three renderer declarations: gtest's EXPECT_THROW macro discards the
     expression result inside its unreachable-code suppression, so nodiscard would fail the -Werror build.
  5. ctest -R is a case-sensitive regex; gtest suite names are CamelCase (ReportText...) so gtest_discover_tests
     uses TEST_PREFIX "report:" -> every discovered case matches `ctest -R report`.
  6. CMake -D values are already string literals; re-stringifying them with a STR() helper double-quotes the path
     (verified bug: files were written into a directory literally named "/home/...") -> macros are used directly.
  7. The HTML header comment must NOT contain the literal report-data script tag (a naive string-search extractor
     would match it); the comment documents the convention without the exact tag text.
  8. The embedded payload sits between the tags with zero surrounding whitespace so extraction is byte-exact
     (to_json's trailing newline is part of the payload; check_html.py's json.loads is whitespace-tolerant anyway).
  9. Evidence format follows the established convention (todo 1-5 files); appended, never overwritten.
  10. Sibling workers (todos 6/8) were mid-flight in the same tree during this todo (libs/arch + libs/db modified
      at 04:33, after my 04:31 files); the shared build dir briefly failed on their in-flight arch-test target.
