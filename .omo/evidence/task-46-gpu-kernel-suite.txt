ROOT CAUSES (verified in libs/capture-core/src/bundle.cpp):
  1. v0 parser: an unterminated final line parsed identically to a clean
     end-of-file (find('\n') == npos -> end = text.size()); the truncated
     terminator was tolerated as valid.
  2. No committed v1 bundle existed, so the per-blob sha256 recorded in
     blobs.json (todo-46 spec) was never violated by a committed fixture;
     v0 sidecar hashes are computed at load, not checked against a record.

FIX (commit 7202b62 "fix(capture): detect trailing truncation + verify
recorded blob hashes"):
  - v0 parser hardened: a non-empty final line WITHOUT a trailing newline is
    now a schema violation with line + byte offsets ("truncated
    'end-capture-v0' terminator ... file ends at byte N"); the missing-
    terminator error now also carries line + byte. Leniency kept ONLY for
    content after a complete, newline-terminated terminator. Errors name the
    file ("(file: ...)").
  - v1 blob provenance verified EAGERLY at open (LoadBlobs): every recorded
    blob is read and checked against the blobs.json sha256 + size reference;
    mismatch/truncation fails open with "sha256 mismatch for '<blob path>'
    (... truncated at byte N)". read_blob keeps a defense-in-depth re-check.
  - New committed fixture tests/fixtures/capture/v1-sample.bundle/ (v1 dir,
    writer-produced: manifest + events + 2 blobs with recorded sha256;
    NOT `.kcap`-suffixed - `.gitignore` `*.kcap/`). Total fixtures still
    ~1 MB << 64 MB guard.
  - Tests (11/11 now): TruncatedV0FixtureLastByteReportsTerminatorOffset
